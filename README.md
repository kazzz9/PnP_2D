# PnP-NMR 2D

Nuclear magnetic resonance (NMR) reconstruction, denoising, and decoupling using two-dimensional diffusion priors. The Plug-and-Play (PnP) framework combines a 2D UNet diffusion prior with task-specific data constraints for NUS, DOSY, pure-shift, and virtual-decoupling applications.

The project uses a 2D model throughout its workflows. The 3D and 4D NUS notebooks also apply the 2D prior to slices or data blocks; the dimensionality of the data differs from that of the network. One-dimensional training and notebooks are outside the current workflow.

## Environment Setup

Use Python 3.10 and install a PyTorch build compatible with your local CUDA environment.

```bash
cd PnP_2D
conda create -n pnp-2d python=3.10 -y
conda activate pnp-2d

# After installing a suitable PyTorch build, install the remaining dependencies.
pip install -r requirement.txt
pip install scipy matplotlib nmrglue PyYAML jupyterlab ipykernel
python -m ipykernel install --user --name pnp-2d --display-name "PnP-NMR 2D"
```

The dependency file is named `requirement.txt`. Workflows involving NMRPipe processing require NMRPipe and a C shell, such as `tcsh`, to be installed separately. Examples that use an external sampling-mask generator also require the corresponding `libPG_cb.so` library.

## Model Configuration

| Configuration | Model Size | Main Uses |
| --- | --- | --- |
| `config/sr_sr3_64_64.json` | 64 × 64 | 2D training and 3D/4D NUS experiments |
| `config/sr_sr3_256_256_val.json` | 256 × 256 | 2D NUS, DOSY, pure-shift, and decoupling experiments |

Key configuration fields:

- `gpu_ids`: GPU device indices.
- `model.unet`: Network channels, channel multipliers, attention, and residual blocks.
- `model.diffusion`: Input dimensions, channels, and conditional generation settings.
- `model.beta_schedule`: Noise schedules for training and inference.
- `path.resume_state`: Checkpoint prefix.
- `train`: Training iterations, learning rate, validation frequency, and checkpoint frequency.

Checkpoints must match the network architecture and input dimensions. Set `resume_state` to the checkpoint prefix without `_gen.pth`, for example:

```json
"resume_state": "experiments/my_run/checkpoint/I1000000_E100"
```

Inference loads `I1000000_E100_gen.pth`. Resuming training also requires the corresponding `I1000000_E100_opt.pth`. Set `resume_state` to `null` to train from scratch.

## 2D Training

The training entry point is `train_2D.py`, with simulated data generated by `data/dataset_2D.py`. Configure the data, sampling masks, GPU devices, and checkpoint paths for your environment, then run:

```bash
python train_2D.py -c config/sr_sr3_64_64.json -p train
```

Training records the loss, periodically generates validation samples, and saves model and optimizer states. Log, TensorBoard, checkpoint, and result paths are managed through the configuration and experiment utilities.

## Reconstruction and Data Processing

Start Jupyter from the project root and select the **PnP-NMR 2D** kernel:

```bash
jupyter lab
```

Configure the input data, sampling masks, pretrained checkpoints, and output paths for the selected task, then run the relevant notebook cells in order.

| Application | Notebook | Configuration (under `config/`) |
| --- | --- | --- |
| 2D NUS reconstruction | `test_nus_2D.ipynb` | `sr_sr3_256_256_val.json` |
| 3D NUS reconstruction | `test_nus3D.ipynb` | `sr_sr3_64_64.json` |
| 4D NUS reconstruction | `test_nus_4D.ipynb` | `sr_sr3_64_64.json` |
| 2D DOSY | `test_dosy_2D.ipynb` | `sr_sr3_256_256_val.json` |
| Pure-shift | `test_PS_real.ipynb` | `sr_sr3_256_256_val.json` |
| Virtual decoupling (VD) | `test_VD_real.ipynb` | `sr_sr3_256_256_val.json` |
| CA decoupling | `test_CaVD_real.ipynb` | `sr_sr3_256_256_val.json` |

### NUS Reconstruction

`test_nus_2D.ipynb` covers data loading, undersampling-mask generation, observation preparation, blockwise reconstruction, and result assembly.

`test_nus3D.ipynb` applies the 2D 64 × 64 prior to slices of 3D data. Its workflow includes NMRPipe data loading, real and imaginary component processing, slice reconstruction, and volume assembly. `test_nus_4D.ipynb` and `test_nus_4D_real.py` support 4D NUS experiments.

### DOSY, Pure-Shift, and Decoupling

`test_dosy_2D.ipynb` applies the 2D prior to DOSY processing and includes visualization and postprocessing cells.

`test_PS_real.ipynb` supports pure-shift experiments, with related processing utilities in `test_real_data_ps/`.

`test_VD_real.ipynb` and `test_CaVD_real.ipynb` provide virtual-decoupling and CA-decoupling workflows, respectively. Select the visualization and MAT export cells needed for your experiment.
